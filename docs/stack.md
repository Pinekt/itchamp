# Технологический стек: лицензии и импортонезависимость

Кейс требует, чтобы технологии были **отечественными или патентно чистыми**
(open-source с разрешительной лицензией), а **ОС и СУБД — из реестра
российского ПО**. Документ фиксирует, что именно используется, на каких
условиях и где мы этому требованию пока не соответствуем.

Лицензии в таблицах ниже взяты из метаданных установленных пакетов, а не
из памяти: их можно перепроверить одной командой (см. конец документа).

## Прикладные зависимости

Все — с разрешительными лицензиями (MIT / BSD / Apache-2.0). Ни одной
копилефт-лицензии (GPL, AGPL, LGPL), то есть нет требования раскрывать
исходный код производных работ и нет патентных ограничений на использование.

## Интерфейс: внешних зависимостей нет вообще

`frontend/` — 1018 строк собственного HTML, SVG и JavaScript. **Ни одной
внешней библиотеки, ни одного обращения к CDN**: ни React, ни Chart.js, ни
шрифтов Google. Проверяется поиском по каталогу — внешних ссылок нет.

Это не аскетизм, а требование к целевой среде. Рабочее место оператора на
предприятии стоит в закрытом сегменте сети без выхода в интернет; страница,
которая тянет библиотеку с CDN, там просто не отрисуется. Мнемосхема и график
телеметрии нарисованы на голом SVG именно поэтому.

Побочные выгоды: нет цепочки поставок npm (то есть нечему быть
скомпрометированным), нет сборки фронтенда, и разбор получасовой тренировки
открывается за 93 мс вместе с графиком.

## Где мы требованию пока не соответствуем

Честный список. Все три пункта — про **среду развёртывания**, а не про код:
приложение не зависит ни от одного проприетарного компонента, поэтому переход
не требует переписывания.

### ОС демонстрационного стенда — Ubuntu 24.04, не из реестра

Целевая ОС — **Astra Linux Special Edition** (реестр российского ПО).
Что для перехода нужно:

- заменить базовый образ в `Dockerfile` на образ на базе Astra Linux —
  приложению нужен только Python 3.11+ и `libargon2`;
- либо развернуть без Docker: зависимости ставятся в виртуальное окружение,
  служба запускается через systemd. Проприетарных бинарей в стеке нет,
  собственных расширений на C мы не пишем.

Текущий стенд на Ubuntu — это площадка для командной работы и записи
демонстрации, а не поставка.

### СУБД — PostgreSQL 16 из upstream, а не Postgres Pro

В реестре российского ПО значится **Postgres Pro**. Мы работаем через
SQLAlchemy и драйвер asyncpg, то есть на уровне стандартного диалекта
PostgreSQL: специфичных для upstream расширений, типов и функций в схеме нет.
Переход — это смена образа и строки подключения `DATABASE_URL`, схема и
запросы не меняются.

Проверяемое следствие: те же 95 автотестов гоняются и на PostgreSQL, и на
SQLite (`.github/workflows/tests.yml`). Код не завязан на одну конкретную
реализацию, и это не заявление, а то, что проверяется на каждый push.

### Docker — удобство, а не необходимость

Контейнеризация упрощает развёртывание, но обязательной не является:
`deploy/install.sh` можно заменить нативной установкой. Если у заказчика
Docker не разрешён, теряется только однокомандный запуск.

## Что можно утверждать без оговорок

- **Патентная чистота.** Все зависимости — MIT, BSD или Apache-2.0. Ни одной
  копилефт-лицензии, ни одной лицензии с патентными ограничениями.
- **Отсутствие внешних вызовов во время работы.** Приложение не обращается ни
  к одному внешнему сервису: ни телеметрии, ни лицензионных проверок, ни CDN.
  Работает в сети без выхода в интернет.
- **Argon2id** — победитель Password Hashing Competition, открытый алгоритм
  без патентных обременений. Не проприетарная схема и не самодельная.
- **ИИ работает локально.** Сейчас `backend/ai_module.py` — правила поверх
  состояния установки, без внешних вызовов. Планируемая замена на обучаемую
  классификацию — scikit-learn (BSD-3-Clause), тоже локально; в зависимостях
  его пока нет, добавит Константин вместе с моделью.

  Внешние языковые модели и облачные API не используются и не планируются:
  рабочее место стоит в закрытом сегменте, обращение к внешнему сервису там
  невозможно физически, а передача данных о действиях персонала наружу
  недопустима по ИБ.

## Как перепроверить лицензии

```bash
pip install -r requirements.txt -r requirements-dev.txt
python - <<'PY'
from importlib.metadata import metadata, distributions
for d in sorted(distributions(), key=lambda d: d.metadata["Name"].lower()):
    m = d.metadata
    lic = (m.get("License-Expression") or m.get("License") or "").strip()
    clsf = [c.split("::")[-1].strip() for c in (m.get_all("Classifier") or [])
            if c.startswith("License ::")]
    print(m["Name"], m["Version"], lic if lic and len(lic) < 40 else (clsf[0] if clsf else "?"))
PY
```

Список зависимостей и их версии закреплены в `requirements.txt` — версии
указаны точно (`==`), поэтому состав поставки воспроизводим и проверяем.
