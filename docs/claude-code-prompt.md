## Что уже сделано

Стек: Python + FastAPI, WebSocket для real-time, веб-UI с SVG-мнемосхемой,
PostgreSQL (SQLAlchemy async, asyncpg) с fallback на SQLite, Docker Compose.

- Движок симуляции с упрощённой динамикой узла и **исполнением сценариев:
  отказы срабатывают по времени** (`trip`, `pressure_up`, `heater_off`).
- Сессии тренировки: старт / сброс / завершение выбранного сценария.
- **Схема БД: 9 таблиц** — `users`, `audit_log`, `scenarios`, `scenario_steps`
  (эталонные шаги), `training_sessions`, `operator_actions` (с временем реакции),
  `telemetry`, `detected_errors` (выход ИИ), `assessments` (баллы и вердикт).
  Схема спроектирована так, чтобы закрывать критерии: ИБ, ИИ, оценка квалификации.
- Начальные данные создаются автоматически: три пользователя с ролями
  (operator / instructor / admin), три сценария с эталонными шагами.
- Оценка квалификации: 100 баллов минус штрафы за ошибки, порог сдачи 70,
  вердикт «сдал / не сдал».
- REST API: сценарии, эталонные шаги, сессии, журнал, ошибки, оценка.
  WebSocket `/ws`: управление сессией и команды оператора.
- Docker: `docker compose up --build` поднимает тренажёр (8000),
  PostgreSQL `ktk_eloyavt` (5433) и pgAdmin (5050).

3. **Сравнение с эталоном** — сопоставлять действия из `operator_actions`
   с `scenario_steps` (пропущенный шаг, нарушен порядок, вышел за окно времени).

4. **Стабильность и производительность** — критерий требует замеров времени отклика
   и задержек. Нужны замеры и, желательно, автотесты ключевых сценариев.
